# Review before the switch — November 2026

Three independent reviewers read the rebuild on 15 November 2026 without the builder's notes: one on **data safety** (storage, sync, merges, backup), one on **learning logic** (old pages against the new code, run side by side), one on **the brief and switch readiness**. This file records what they found, what was fixed the same day, and what is still open. The decisions are in DECISIONS.md (2026-11-15).

## What held

- Every storage key of the old pages is in the registry under the same name; the merge rules gave identical results to the live `sync.js` on 20,000 random inputs each.
- The scheduler equals the old one for every record and answer (apart from the hard-card rule, now restored); 7,650 answers against all 378 questions were marked the same by old and new.
- Question ids, the noun list, Lernpfad items, streak and shield, concept lifecycle and badges match.
- No path from content or synced data into HTML; the family code is never exposed; staging never touches the live keys or the cloud.

## Fixed on 15 November

**Sync and backup**
- One entry that cannot be merged, written or uploaded no longer blocks all other keys.
- An unload flush cannot put a stale copy on top of the cloud before the page has merged once.
- An answer saved while a push waits for the cloud is no longer overwritten.
- Bringing back a snapshot did nothing or was undone; it now merges in and pushes at once, and says what it did.
- Per-module day counters reach both devices (`plan_days_<P>` merged in depth).
- A refused daily snapshot is visible in the error log.

**Learning**
- "Nochmal" planned from the previous round's card list: the same cards repeated, boxes climbed too fast, no new words. Every round is now planned from the records as they are.
- Grammar sentences counted as "new words" and used up the day's new-word limit.
- The home button's round carried no grammar items, so Festigen and the Meister-Check could never move for a child who uses the main button.
- A Gold concept's sentence could be booked on another concept.
- A gender mistake in a sentence no longer sent the noun back for review; Nomen-Bausteine article questions did not touch the noun.
- A miss in Wort-Regen brought the word back days later instead of today.
- The trainer's ±1 day was never applied; re-asked sentences were counted twice.
- Daily training took due cards first; the old trainer reserves the new words first. Topic rounds were limited to 5 new questions; the old quiz had no limit.
- Hard cards followed a fading rule; the old rule is back for the existing modules.
- The round history changed scale (0–1 instead of 0–100).

**Screens and start-up**
- On a second device, confirming "Profil gefunden" could overwrite grade and gentle mode for the whole family.
- The grade was stored but never used; the last profile opened silently on a shared tablet; an old link naming the other child opened the wrong data.
- Home tiles counted other modules' cards; the progress ring stayed empty.
- The Italian line was off after the first start. (The review switched it on; the owner reversed that the same day: German only is the standard, 🇮🇹 shows the Italian lines — see DECISIONS.)
- One failed content file left a child on a single sentence; a failed start left a blank page.
- A reload shortly after an update could pair new code with old code; an open tab never updated.
- Sound could stay silent on iOS for the first word; the device voice could talk over a clip.

## Open — needs the owner or a device

1. **Never run against the real cloud.** The new sync has only met a fake. Before the switch: one staging run with the sync on and a throwaway family code on both devices, and a look at the deployed Firestore rules (do they allow `snapshots/`? is the real code 16–64 characters, as the draft rules demand — count, never show it).
2. **A backup export from a device**, loaded into the staging app, so the first run is tried on real data. Also needed to carry over anything changed in the old in-app editor (`wq_editor_QB*` is not read by the new app).
3. **The switch itself is not built**: root shell, the two forwarders (they must pass `profil` and `familie`), `legacy/`, the personal-data check's file list, removal of `next_*` copies. An old trainer tab reloads itself only if the forwarder carries a higher `APP_VERSION`; the old quiz and game need one manual reload per device.
4. **True roll-back.** With "more practice wins" merges no device can lower a wrong value alone. Until a restore marker exists, the parachute for the switch is: the backup file + the snapshot merge (both refill, neither lowers).
5. **Each child's grade** must be set once after the switch (the old pages had it in the code).
6. **To try on the real iPad and iPhone:** sound on the first tap, the keyboard over "Prüfen", home-screen mode (its storage is separate from Safari's; no address bar for the family link), touch targets below 56 px (icon buttons 44 px, footer links), three answer columns on the phone.

## Open — decisions on differences that remain

- New-card limits and the 50-answer goal are pooled across modules in the home button's round (the old pages each counted for themselves).
- Re-asking a missed card later in the same round is new (it changes no record).
- The day changes at midnight in Germany (the old pages used UTC); a round keeps the day it started on.
- Mixed and trainer rounds no longer appear in the old round history.

## Open — before the next module

- No engine registry yet: a module of a new kind (map quiz) needs a loader, a validator branch, a renderer and a place in the session core (the reviewers' friction list: `main.js` module loading, `validate-content.mjs` engines, `session.js` checker import, the session screen's renderer table).
- Higher rungs of a ladder never send a child back a rung; lower rungs stay in rotation. To be decided with the map module.
- CI does not gate the Pages deploy; the smoke test runs one iPad viewport on an empty profile.
- A full or blocked storage is silent (the answer is accepted, nothing is saved).
- Eltern mode is open to children (restore and import are two taps); no screen for a test date yet.
- The public docs describe the children without names (older/younger child, grades); the history clean-up (phase 6) should take that out too.
